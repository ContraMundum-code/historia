# B 标注首批交付与复核说明

本批统一使用简体，保留三张现有标注表的英文表头，不修改数据库、人物词典或原始语料。
这是提交组长审核的首批数据，事件采集尚未完成，身份也是初标，不能视为全量终审结果。

## 本批内容

- `event.csv`：5 个事件，来自李揆、独孤郁、令狐楚、郑余庆、刘禹锡的本传。
- `eventParticipant.csv`：6 条参与记录，只引用现有人物库的 ID。
- `personCategory.csv`：518 条身份初标，覆盖全名单 374 人；其中 141 人暂标“其他”并待复核。
- `bEventEvidence.csv`：逐事件说明相对纪年的承接关系、换算依据和地点填写依据。
- `bReview.csv`：缺失参与者 ID、年份不明、官职日期异常，以及逐人的“其他”待复核项。
- `scripts/annotations/categoryRules.csv`：官职映射规则；`manualCategories.csv`：带原文依据的补充判断。

身份补充判断由 AI 辅助阅读现有语料、筛选证据，并非已经经过同学人工终审。
按现有 CSV 规范填写 `source=manual, confidence=1.0`；此处的 1.0 是规范约定值，
不代表 AI 判断正确率达到 100%，也不代表组长已经认可。规则结果同样需要复核。

“其他”是未完成确认的占位，证据列和复核表均明确说明原因；它不表示此人没有文学、思想或政治身份。
本批采用较窄官职规则，因此会漏掉部分真实身份。后续应优先逐人处理复核表，补充可追溯的证据，
替换占位，而非为了数量自动把普通官员全部归为政治家。

## 缺失数据如何处理

| 情况 | 当前处理 | 后续操作 |
|---|---|---|
| 原文没有事件地点 | `location` 留空 | 找到可靠原文后补入；贬任目的地不能当作案发地 |
| 只有相对纪年 | 在证据表写出同篇年号承接及换算 | 无法确认承接关系时不录入事件 |
| 年份仍不确定 | 不进入事件主表，写入复核表 | 核实后再收录，不用任官区间猜年份 |
| 参与者有姓名但不在 374 人库 | 不写空 ID、0 或虚构 ID，记录缺失姓名 | 由组长决定是否另行扩库；本 PR 不扩库 |
| 同列、官员等未具名 | 不生成虚构人物 | 可在描述保留原文事实 |
| 身份没有可靠证据 | 暂标“其他”，逐人列入复核表 | 人工确认类别并补出处后替换 |
| 官职年份早于出生或晚于去世 | 该官职行不作为规则证据 | 保留原始数据，由组长另行校对 |

具体缺 ID 者包括吐突承璀、韦正牧、于翬、裴度。当前参与者表只表达已入库人物的参与关系，
不是事件的完整人物清单。刘禹锡事件中的宪宗以现有人物 ID `166933` 对齐。
郑余庆的“司徒，first_year=728”早于生年 746，该行已排除；原始官职表不作改动。

郑余庆事件的“两京国子监”表示奏修对象的所在地，不表示上奏地点。若项目把 location
严格限定为行为发生地，可在审核时留空；李揆事件的“凤州”有原文明载。

## 身份规则的边界

规则采用完整官职名匹配，先排除赠官、检校、致仕以及有明确生卒冲突的行。
宰相同时标政治家；明代大学士只映射政治家，不映射宰相。
不把翰林学士自动映射为文学家，不把“节度使掌书记”、武散阶自动映射为将领。
中书令有虚衔风险，本批不据这一官名自动判相。没有另行推导“军事家”。
仍有需要审核的边界，如某些平章事、大学士是否属于实际任职，需要回到本传确认。

补充判断只针对本传本人，剔除了父、子、其他人善诗文，以及引《诗经》、获赐他人文集等误命中。
补充表可独立修改，修改后重新生成主表，避免直接改主表后丢失判断依据。

## 本地操作

在仓库根目录运行，使用 Python 标准库，不新增项目依赖：

```text
python scripts/annotations/deriveCategory.py
python scripts/annotations/checkAnnotations.py
```

生成脚本只重建 `personCategory.csv` 的数据部分，保留其已有第一行字节。
编辑前应先同步最新分支；不要在其他同学已有新增行时直接重生成并覆盖，先把新增身份
及其依据合并入补充表，核对结果后再提交。

校验包括表头、列数、重复项、人物 ID、角色、身份词表、374 人覆盖、描述长度、
引文逐字存在性（身份引文允许语料人工折行差异）、生卒约束、占位复核记录和身份生成一致性。
程序不能判定所有历史解释是否正确，仍需要读原文审核。
本检查只覆盖 B；C 测试集与弱标注隔离尚未进行，不能把本次通过视为整个项目验证通过。

## 审核后继续做

1. 先确认五个事件的粒度、描述、角色，以及缺 ID 处理方式。
2. 逐人处理 `bReview.csv` 的身份占位；修改补充表时保留英文表头。
3. 继续从现有语料摘录同时满足动作、年份、人物的事件，按事件名和年份跨传去重。
4. 每个新事件一起补参与者和证据；不能确认的写入复核表。
5. 校验后分批提交，写明新增事件数、参与记录数和身份复核进度。

数据库种子中的身份词表是否包含“其他”需组长在入库前确认。本 PR 仅记录该兼容事项，
不修改任何 SQL 或数据库配置，也不执行导入。PR 交由组长审核、决定合并。
