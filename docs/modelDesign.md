# 关系分类模型设计

项目只训练一个模型：句子级人物关系分类器。本文说明它的输入构造、标签体系、结构、训练配置、
推理链路与评测方式。人物识别由词典与 HanLP 完成，消歧由别名词典与共指规则完成，这两部分
不属于本文范围。

## 一、任务定义

给定一句话和句中两个已识别、已对齐 `person_id` 的人物，判断这两人属于哪一类关系。

一句话里出现 n 个人物时枚举 C(n,2) 对，每对单独判定，同一句话送进模型多次，每次标记
不同的实体位置。模型不负责判断句中有谁，也不负责判断这两个人是谁。

## 二、标签体系

七类，六类关系加一类「无关系」。

| 标签 | 含义 | 对称性 |
|---|---|---|
| 师生 | 授业、受业、问学 | 有向 |
| 家族 | 父子、兄弟、叔侄、姻亲 | 对称 |
| 朋友 | 交游、友善、唱和 | 对称 |
| 合作 | 共事、举荐、同谋、同朝 | 对称 |
| 对立 | 弹劾、党争、交战、构陷 | 对称 |
| 君臣 | 君主与臣属 | 有向 |
| 无关系 | 仅同句共现，无关系或无法判定 | — |

「无关系」不可省略。全部语料中含两人以上的句子 1,126 句，按组合数计算候选关系对约 1,773 个，
其中真正存在关系的不足三成。缺这一类，模型会把每一对共现都塞进六类之一，图谱里长出大量假边。

有向关系在输入中固定头实体、尾实体顺序，头为施动方。

现有关系分布（`data/dictionaries/relations.csv`，1,426 条）已明显不平衡：师生 450、家族 331、
合作 261、朋友 264、对立 100、君臣 20。训练时按类别频次的平方根取倒数加权，君臣类权重最高。

## 三、输入构造

单句加实体位置标记，不拼接上下文段落。

```
轼 与 辙 同登 进士 第
轼 与 [E1] 辙 [/E1] 同登 进士 第              → 家族
```

标记用 `[unused1]`、`[unused2]` 包住头尾实体，模型词表自带、不需扩表，这是 R-BERT 一类的
标准做法。同一句话为每一对候选各构造一个样本：

```
「轼与辙同登进士第，王安石方用事」
  (轼, 辙)     → 家族
  (轼, 王安石) → 无关系
  (辙, 王安石) → 无关系
```

分隔符统一为句子自身标点，不做截断。SikuBERT 最大长度 512 token，古籍单句通常不足 50 字，
用不满，多出的预算留给少数长句（本纪连排任命可达数百字）。

## 四、模型结构

```
输入 token ids + [unused1]/[unused2] 标记
  → SikuBERT（12 层 RoBERTa，768 维，古籍语料预训练）
  → 取 [CLS] 表示 h ∈ R^768
  → Dropout(0.1)
  → Linear(768, 7)
  → Softmax
```

全参数微调，不冻结编码器。分类头新建，初始化用正态分布 σ=0.02。

## 五、训练数据

| 数据 | 规模 | 用途 | 来源 |
|---|---|---|---|
| 弱标注 | 3,000–5,000 条 | 训练 | 触发词规则扫全部 330 篇本传 |
| 人工测试集 | 300 句以上 | 评测 | 逐句人工标注 |

弱标注由规则生成：命中「从学」「受业」「问学于」判师生，命中「父」「子」「兄」「弟」「从子」
判家族，命中「与……善」「友善」判朋友，命中「共」「同」「荐」判合作，命中「劾」「讨」「攻」
判断立，命中「拜」「擢」「诏」判君臣，未命中任何规则判无关系。

测试集从含两人以上的 1,126 句中挑，标注规则见 `annotationGuidelines.md`。测试集只做评测，
不参与训练、不参与调参、不参与早停。训练集与测试集按文献和人物切分，同一人物的句子不会
同时出现在两侧。

弱标注切分：按人物留出 10% 做验证集，早停看验证集 macro-F1。

## 六、训练配置

| 项 | 取值 |
|---|---|
| 优化器 | AdamW |
| 学习率 | 2e-5 |
| batch | 16 |
| epochs | 3–5，早停 |
| 最大长度 | 512 token |
| 损失 | 交叉熵，类别加权 |
| 硬件 | 单卡，约十分钟一轮 |

## 七、推理链路

模型只处理单句，长文本由外层切分与聚合承接。

```
整段文本
  → 切句（。！？）
  → 词典匹配 + HanLP 补充 → 句中 n 个已对齐 person_id
  → n < 2 跳过；n ≥ 2 枚举 C(n,2)
  → 逐对构造样本送模型
  → 置信度 ≥ 0.6 保留
  → ±2 句窗口内同一人物对投票聚合，取加权最高类别
  → 输出至图谱边，附证据句
```

窗口聚合是跨句关系的唯一来源：「辙，轼之弟也」给出家族，「后同贬岭南」给出共同遭遇，
两句分别投票，家族类权重高于合作类。

「其弟」「从子」「之孙」这类不带姓名的称谓无法被 NER 匹配，配对阶段直接丢失。这部分靠
亲属称谓词加前文最近人物的规则补齐，属于独立模块，不在模型内。

## 八、评测

主指标 macro-F1，副指标各类别的 P / R / F1 与混淆矩阵。macro 而非 weighted，因为君臣类
样本极少，weighted 会把它稀释到看不见。

四行对照：

| 方法 | 定位 | 说明 |
|---|---|---|
| 触发词规则 | 下限 | 零训练成本，直接反映规则覆盖 |
| TF-IDF + 逻辑回归 | 经典基线 | 判断词袋特征是否够用 |
| SikuBERT 微调 | 本项目模型 | 全参数微调，类别加权 |
| 大模型零样本 | 上限参照 | 同一测试集，提示词固定 |

第四行回答「通用大模型已能做这件事，为何仍训练专用模型」。四个结果并列呈现，不单独汇报
本项目模型。

## 九、已知限制

单句建模，跨句关系依赖窗口聚合，多跳推理不支持。

指代未消解的句子直接跳过，不猜测。

君臣类训练样本不足百条，指标波动大，报告时给出置信区间。
